# 页面适配说明

记录平台网页端的实际结构，作为页面适配层的依据。平台页面可能随时变化，每次核实需注明日期；与本文不符时以真实页面为准，并更新本文和 PRD。

本文只记录结构、类名和参数格式，不记录账号信息、真实岗位、公司或招聘者姓名。

## 2026-11-26 只读核实

- 环境：Chrome 桌面版，已登录求职者账号，页面 `https://www.zhipin.com/web/geek/jobs`。
- 方式：只读取 DOM、点击卡片查看详情、切换原生筛选和滚动列表；未点击「立即沟通」。
- 未登录时搜索页不渲染岗位列表。

### 搜索与筛选（H-05）

| 项目 | 观察结果 |
| --- | --- |
| URL 参数 | `query`（关键词）、`city`（城市代码，如北京 `101010100`）、`salary`、`experience`、`degree`、`jobType` |
| 直接打开带参数的 URL | 整页加载，筛选生效，对应筛选框显示「名称(1)」 |
| 页内切换筛选 | 单页应用内更新：URL 参数同步改变，列表重置为第一批，不整页重载 |
| 选中状态 | 筛选框容器 `.condition-filter-select`，当前值区 `.current-select`；已选项带 `active` 类 |
| 搜索框提交 | 单页应用内更新；**观察到提交后 `city` 参数被改成另一个城市**，页面不一定提示 |

筛选项的 `ka` 属性格式为 `sel-job-rec-<类型>-<代码>`，代码与 URL 参数值一致：

| 筛选 | 代码 |
| --- | --- |
| 求职类型 `jobType` | 全职 1901、兼职 1903、实习 1902 |
| 薪资 `salary` | 3K以下 402、3-5K 403、5-10K 404、10-20K 405、20-50K 406、50K以上 407 |
| 经验 `experience` | 在校生 108、应届生 102、经验不限 101、1年以内 103、1-3年 104、3-5年 105、5-10年 106、10年以上 107 |
| 学历 `degree` | 初中及以下 209、中专/中技 208、高中 206、大专 202、本科 203、硕士 204、博士 205 |

适配结论：每个关键词通过构造带全部参数的 URL 整页打开，不使用搜索框；加载后核验 URL 中的 `query`、`city` 及各筛选参数与配置快照一致，且筛选框显示已选，否则暂停。整页打开属于插件自身导航，按 PRD §9 使用导航令牌恢复。

### 列表加载（H-03）

- 列表容器 `.job-list-container`，卡片 `li.job-card-box`。
- **滚动加载，无分页器**：每批 15 条，滚动到底后追加下一批；加载中出现 `.loading-wait`。
- 适配结论：一个批次即一次追加的 15 条；以新增卡片的岗位 ID 判断是否有进展。

### 卡片字段（H-04）

| 字段 | 位置 | 说明 |
| --- | --- | --- |
| 岗位链接、ID | `a.job-name` 的 `href` | 形如 `/job_detail/<ID>.html`，不带查询参数；ID 为字母数字串 |
| 标题 | `a.job-name` 文本 | 明文 |
| 薪资 | `.job-salary` | **数字经字体混淆**：字体 `kanzhun-mix`，数字为私有区码位（U+E03x），文本中只剩 `-`、`K` 等 |
| 经验、学历 | `.tag-list li` | 明文，第一项经验、第二项学历 |
| 公司 | `.job-card-footer .boss-name` | 类名虽为 boss-name，内容是公司名 |
| 地点 | `.company-location` | 明文 |
| 在线状态 | `.boss-online-icon` | 仅图标 |

卡片上没有招聘者标识。

### 详情区与沟通入口（H-02 部分、H-06 部分）

- 列表右侧为详情区 `.job-detail-container`。点击卡片（`.job-info` 区域）后详情区就地更新，**URL 不变**。
- 详情区包含指向同一 `/job_detail/<ID>.html` 的链接，可用于核验详情区与当前卡片一致。抽查 8 张卡片全部一致。
- 沟通按钮：`.job-detail-op a.op-btn.op-btn-chat`，`href="javascript:;"`，文本「立即沟通」。
- 招聘者区 `.job-boss-info`：`h2.name` 显示姓名和职务，`.boss-online-tag` 或活跃文本（如「刚刚活跃」）；**无稳定招聘者 ID**。
- 职位描述 `p.desc` 中插入了隐藏的干扰文本节点（反抓取），首版不读取职位描述。
- 抽查的卡片均显示「立即沟通」，未遇到已沟通岗位，**H-02 未核实**。

## 2026-11-26 真实点击核实（H-01、H-06、H-02）

- 方式：用户本人在观察标签页点击一次「立即沟通」，插件侧只记录 DOM、URL 和 `window.open`，不做任何点击。平台已开启默认招呼语。
- 记录中不保存招呼语正文。

### 点击后的时序（H-01、H-06）

| 相对点击 | 现象 |
| --- | --- |
| 0 ms | 点击 `.job-detail-op a.op-btn-chat`（文本「立即沟通」，`href="javascript:;"`，无 `target`） |
| 约 15 ms | 按钮类名增加 `is-disabled` |
| 约 450 ms | 插入弹窗 `.greet-boss-dialog`：标题 `.greet-boss-header` 文本「已向BOSS发送消息」，正文 `.greet-con` 为平台默认招呼语，提示 `.warm-tip`，底部 `.greet-boss-footer` 有 `a.cancel-btn`「留在此页」和 `a.sure-btn`「继续沟通」 |
| 约 1.8 s | 弹窗从 DOM 移除，按钮恢复为 `op-btn op-btn-chat`，文本仍为「立即沟通」 |

- 全程在当前标签页，路径保持 `/web/geek/jobs`，未跳转会话页，未调用 `window.open`。
- 详情区岗位 ID 在点击前后不变。
- 弹窗在约 1.8 秒后消失；未确认是用户关闭还是平台自动关闭，适配层不能依赖它常驻。

适配结论：成功证据为点击后出现 `.greet-boss-dialog` 且标题为「已向BOSS发送消息」，同时详情区岗位 ID 与点击前一致。使用 MutationObserver 捕获，超时（建议 5 秒）未出现即待核对。弹窗仍在时只可点击 `cancel-btn`「留在此页」，不得点击 `sure-btn`。

### 已沟通状态（H-02）

- **列表页详情区不会更新**：成功后同一岗位的按钮仍显示「立即沟通」，卡片上也没有已沟通标记。因此列表页的按钮状态不能作为成功证据，也不能单独作为去重依据。
- 单独的岗位详情页 `/job_detail/<ID>.html`（服务端渲染）对已沟通岗位显示 `a.btn.btn-startchat`「继续沟通」，跳转目标指向 `/web/geek/chat`；未沟通岗位显示「立即沟通」。
- 尚未确认：列表页刷新后再选中已沟通岗位时，详情区是否显示「继续沟通」。

适配结论：跨任务去重以插件本地记录为准；在插件安装前已在平台沟通过的岗位，首版可能无法识别，重复点击时平台的反应未知，需在 M2 页面测试中确认。

## 2026-11-26 首版验收中的补充核实

### 无结果页

- 没有 `.job-list-container`，也没有 `.loading-wait`。
- 显示 `.job-recommend-result > … > .job-empty-wrapper > .job-empty-box`，文本「没有找到相关职位，打开 APP，查看全部职位库，优质职位随心聊。」
- 平台对不存在的关键词通常仍返回相关岗位，只有筛选条件组合过窄时才出现此页。

适配结论：`.job-empty-box` 可见即判定为无结果，换下一个关键词。

### 求职类型为「兼职」时的筛选栏

- 筛选框变为「求职类型、结算方式、兼职时间、工作经验、学历要求、公司规模」，没有「薪资待遇」，URL 中的 `salary` 参数不生效。

适配结论：配置校验不允许「兼职」与薪资档位同时设置。

### 页面反调试

- 用浏览器自动化工具开启控制台日志监听后，搜索页约 5 秒内退回上一页；只读 DOM 不受影响。
