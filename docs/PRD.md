# BOSS 直聘自动打招呼插件产品需求文档

| 项目 | 内容 |
| --- | --- |
| 产品名称 | BOSS Greeting Assistant |
| 文档版本 | 0.3 |
| 编写日期 | 2026-11-26，Australia/Brisbane |
| 状态 | 需求基线；M1 已实现，页面假设 H-01–H-06 已核实（H-02 部分不成立） |
| 目标实现版本 | v0.1.0 |
| 使用形态 | 个人使用、单账号、Chrome 桌面浏览器扩展，Manifest V3 |

## 1 产品目标

用户设置岗位条件后，插件在本人已登录的 BOSS 直聘网页中自动搜索岗位、筛选，并通过平台的「立即沟通」入口以平台默认招呼语发起沟通，减少反复搜索、点击和记录的时间。任务启动后无需逐个岗位确认。

本产品的首版结果是“已发起沟通”，不将其称为“已发送简历”。附件简历及 HR 回复后的操作由用户在原平台处理。

## 2 已确定的范围和实现假设

已由用户确定：自动找到符合条件的岗位并打招呼；首版不处理附件简历发送；先完成 PRD 并建立公开 GitHub 仓库，再进行后续开发。

PRD 0.2 由用户确定：首版招呼语以平台默认招呼语为唯一发送路径，插件不填写或发送自定义文案；首版筛选不在现有薪资、经验、学历、求职类型、排除关键词和排除公司之外新增条件。

PRD 0.3 由用户确定：卡片薪资数字经平台字体混淆，插件不解码；薪资条件改为选择平台原生薪资档位，由平台筛选。

为使首版可以直接开发，采用以下可调整的产品决策：仅支持 Chrome 桌面端；每个浏览器配置文件按单账号使用；每次任务使用一个由用户在平台上选定的城市；首版不依赖模型 API 或服务器。Edge 兼容、自动跨城市切换和账号切换识别留待后续验证。

## 3 首版范围

| 范围 | 功能 |
| --- | --- |
| 必须实现 | 多关键词依次搜索、当前城市搜索、薪资和经验学历筛选、公司和关键词排除、自动打招呼、发送核验、历史去重、任务上限、开始与停止、进度日志、异常暂停 |
| 后续考虑 | 插件内自定义招呼语、AI 匹配、按 JD 定制招呼语、HR 活跃度筛选、猎头或外包标识排除、公司规模和融资阶段筛选、自动切换城市、统计报表、历史导入导出 |
| 首版不实现 | 附件简历发送、在会话中填写或追加任何消息、HR 回复监测与自动回复、全天无人值守、多账号、跨招聘平台、绕过验证码或平台额度、调用未授权的平台私有接口 |

## 4 用户流程

1. 用户自行登录 BOSS 直聘，在平台中开启并设置默认招呼语，进入岗位搜索页，选择城市。
2. 首次使用时，插件展示一次风险与平台规则说明，用户确认后才可开始任务；确认记录保存在本地。
3. 打开插件，填写关键词、筛选条件、本次发送上限和操作间隔。
4. 插件展示当前城市、配置摘要及“将使用平台默认招呼语”的提示。用户点击“开始”即授权按这些规则执行本次任务，无逐岗确认步骤。
5. 插件依次搜索每个关键词，等待搜索结果更新并验证搜索词和筛选条件生效。
6. 对当前批次岗位提取字段，筛选、去重，按页面顺序串行处理。
7. 定位当前岗位的「立即沟通」入口，点击后核验平台默认招呼语已发送，保存记录。
8. 当前批次结束后加载下一批（翻页或滚动加载，以真实页面为准）；当前关键词没有更多结果或达到扫描批次上限后，转到下一关键词。
9. 达到本次或当日额度、全部关键词完成、用户停止或出现阻断异常时结束或暂停，展示结果和原因。

## 5 配置与默认值

以下额度和间隔是产品初始值，不是平台许可或账号安全阈值。日额度按当前浏览器配置文件的本地记录累计，不能覆盖用户在其他设备或原平台的操作。

| 配置 | 默认值与校验 | 行为 |
| --- | --- | --- |
| 搜索关键词 | 必填，最多 10 个；去空白、去重复 | 每个关键词分别搜索，合并结果去重；不能只搜索第一个 |
| 城市 | 使用平台当前选中城市 | 开始时展示城市；无法确认当前城市时不启动 |
| 求职类型、工作经验、学历 | 不限；每类最多选一个平台选项 | 通过平台原生筛选应用并验证；失败则暂停，不静默放宽 |
| 薪资档位 | 不限；可选平台档位 3K以下、3-5K、5-10K、10-20K、20-50K、50K以上之一 | 通过平台原生薪资筛选应用并核验；插件不读取或解析卡片薪资 |
| 排除关键词 | 空 | 在岗位标题、卡片标签和公司名称中做不区分大小写的子串匹配 |
| 排除公司 | 空 | 公司名称做去首尾空白、不区分大小写的子串匹配 |
| 招呼语 | 不在插件中配置 | 使用用户在平台设置的默认招呼语；插件不读取、不修改平台招呼语设置 |
| 本次发送上限 | 20，可设 1–30 | 未核验的发送尝试也占用本次发送额度，避免失败后持续触达 |
| 当日发送上限 | 30，可设 1–30 | 发送前检查并预留额度；同一配置文件跨任务累计 |
| 操作间隔 | 每个发送尝试结束后随机等待 15–30 秒 | 可调，最小值不少于 15 秒，最大值不小于最小值 |
| 每关键词最大批次数 | 5，可设 1–20 | 一个批次指一页结果或一次滚动加载；达到上限后换下一关键词，不视为异常 |
| 非发送操作间隔 | 搜索、翻页、加载之间随机等待 3–8 秒 | 不可低于 3 秒；不计入发送额度 |

空关键词、无效薪资档位、额度越界、无效时间间隔应在开始前提示，不执行发送。运行中配置变更仅对下次任务生效，当前任务使用启动时的配置快照。

## 6 搜索与筛选规则

### 6.1 搜索

每个关键词必须独立提交搜索：插件按配置构造带关键词、城市和筛选参数的搜索 URL 整页打开，不使用页面搜索框（实测其提交可能改变城市）。切换关键词或翻页后，必须确认列表发生更新或页面明确显示无结果，不能仅凭旧卡片仍存在就继续。

结果按平台当前排序遍历，不更改平台排序策略。加载下一批需核验页码、列表标识或新增岗位 ID 的变化；无进展时暂停，禁止循环处理同一批。首版以卡片公开可见字段为筛选依据，不承诺检查完整 JD。

### 6.2 字段与失败处理

| 字段 | 要求 |
| --- | --- |
| 岗位标识、原始链接 | 从明确的岗位详情链接提取稳定标识，去除跟踪参数；不能使用卡片任意第一个链接代替岗位链接 |
| 标题、公司 | 发送前必须能确认；缺失时不发送，记为解析失败 |
| 经验、学历、标签 | 按标签内容识别（不依赖顺序），按用户设置复核：只拦下与设置明确冲突的值；卡片没有对应标签时放行，因为该条件已由平台原生筛选应用并核验 |
| 薪资 | 不提取。卡片薪资数字经字体混淆，解码属于绕过平台措施 |
| 招聘者标识 | 页面可可靠读取时使用；不得猜测、拼接或通过非公开接口补齐 |

薪资只依赖平台原生筛选：每次搜索后核验 URL 中的薪资参数与配置一致且筛选框显示已选，否则暂停。平台档位内的岗位不再逐个按薪资复核。

岗位标题或标签满足任意一个配置关键词即可通过关键词复核，但仍需满足全部硬条件且不命中任何排除项。薪资、经验、学历与求职类型优先通过平台原生筛选设置和可见选中状态核验；若页面筛选语义与配置无法对应，则暂停说明原因，不能声称已筛选。

## 7 打招呼行为与成功判定

### 7.1 发送前检查

发送前重新确认当前详情区展示的岗位、公司与待处理岗位一致，沟通入口仍为「立即沟通」，未命中历史沟通或待核对记录，且存在剩余额度。选择器应限定在当前岗位卡片或详情区范围，并检查元素可见、可交互；不能在整个页面任意选择一个包含“发送”或“沟通”的元素。

同一时刻只处理一个岗位。目标岗位无法确认或出现未知弹窗时，停止后续发送并提示用户处理。

### 7.2 平台默认招呼语

首版唯一发送动作是点击当前岗位的「立即沟通」，由平台发送用户预先设置的默认招呼语。插件不在会话输入框中填写、粘贴或发送任何文字，也不读取或修改平台的招呼语设置。

点击后可能出现以下情况：

| 页面反应 | 处理 |
| --- | --- |
| 出现与当前岗位对应的发送成功提示 | 记为已沟通。提示中若有「留在此页」或关闭按钮且已被识别，可点击它回到列表；不点击「继续沟通」等进入会话的按钮 |
| 跳转或打开会话页，但未见本次默认招呼语 | 可能平台未开启默认招呼语。记为待核对并暂停，提示用户在平台开启默认招呼语；不补发任何文字 |
| 新开标签页或页面离开搜索列表 | 不在新页面上继续操作；记为待核对并暂停 |
| 无任何可识别反应 | 超时后记为待核对并暂停，禁止再次点击 |

不自动关闭未经识别的弹窗，不对验证码、协议同意、身份验证或权限申请按钮执行点击。

### 7.3 成功证据

满足下列证据，且与当前岗位关联，才可标记成功：

- 当前点击后出现新的平台发送成功提示（实测为「已向BOSS发送消息」弹窗），且点击前后详情区岗位 ID 一致。弹窗约 1.8 秒后消失，须在出现时捕获。

列表页详情区的按钮在成功后仍显示「立即沟通」，不能作为成功证据。

“点击成功”“按钮短暂禁用”“等待了一段时间”“弹窗消失”均不单独构成成功证据。

平台提示是页面层面的结果证据，不等于证明 HR 已读、回复或附件简历已发送。

## 8 岗位记录、去重和重试

| 岗位状态 | 含义 | 后续处理 |
| --- | --- | --- |
| 待处理 | 当前任务中符合条件且未处理 | 可以进入发送流程 |
| 本次跳过 | 当前配置不匹配或字段无法判定 | 仅作用于本次任务，下次按新配置重新评估 |
| 已沟通 | 有核验成功记录，或页面可靠显示已有沟通（列表页按钮不可靠，见 §16 H-02） | 跨任务去重，不自动重复发送 |
| 发送前失败 | 已确认尚未触发任何可能发送的操作 | 可重试一次；仍失败则记录，禁止无限重试 |
| 待核对 | 已触发可能发送的操作，但成功与否不明 | 不自动重试，暂停任务；用户核对后手动处理 |

岗位主键以稳定岗位 ID 为准。可可靠确认招聘者相同时，避免在同一任务中对其多个岗位重复发起沟通；只有同公司而无招聘者身份信息时，不将公司等同于同一个人。

任何可能引发平台默认发送的“立即沟通”点击，都应先保存发送尝试记录并占用额度。不能在点击前无记录、点击后页面崩溃的情况下，将岗位当作从未发送。

用户可以对待核对记录标记“已沟通”“确认未发送”或“保留待核对”。“确认未发送”后仅允许用户显式选择重新加入任务，不能自动补发；此前占用的额度不回退。

## 9 任务生命周期与控制

任务状态包括未运行、运行中、暂停、停止中、已停止、已完成和失败。页面展示当前关键词、批次、岗位、处理数量及暂停或结束原因。

- 关闭插件弹窗不终止内容脚本中的任务；重新打开后显示当前页面的真实状态。
- 用户点击“停止”后，不开始新的岗位处理；所有异步等待后、所有发送动作前均须重新检查停止标志。
- 已发出的请求无法撤回；停止过程中尚未核验的发送保留为待核对，不记为成功。
- 插件自身发起的导航（切换关键词、加载下一页、关闭成功提示后返回列表）若导致页面重新加载，任务可恢复：导航前持久化一次性导航令牌和预期 URL，新页面加载后令牌未过期（60 秒）且 URL 符合预期才继续，令牌用后即废。
- 用户手动刷新、手动导航、关闭岗位页或浏览器退出后，不自动恢复发送。重新打开时识别中断任务，保留历史并提示重新开始。
- 同一浏览器配置文件只允许一个自动任务；第二个标签页不得同时启动。任务锁应支持异常释放，但未完成发送记录仍需保留。
- 单次任务异常不能遗留永久“运行中”状态。后台休眠后需能从持久化数据恢复展示，不依赖内存状态。

## 10 异常处理

| 场景 | 必须行为 |
| --- | --- |
| 验证码、账号或访问限制、发送额度提示 | 立即暂停，显示原因，不自动解题、重试或换账号 |
| 登录失效或登录墙 | 暂停，要求用户在原平台登录；不读取密码或验证码 |
| 搜索或筛选条件未成功应用 | 暂停，不继续用旧结果发送 |
| 岗位关闭或明确不可沟通 | 本次跳过并记录原因 |
| 发送被明确拒绝 | 记录失败；涉及限制时暂停，其他情况需确认未发送后才允许重试 |
| 超时或发送结果不明 | 标记待核对并暂停，禁止自动重发 |
| 未知弹窗、找不到目标按钮、目标岗位不明 | 停止发送并显示处理建议，不盲目点击 |
| 连续 3 个岗位解析失败 | 暂停，提示页面可能发生变化 |
| 搜索无结果或下一页不可用 | 换关键词；全部完成后正常结束 |
| 页面标识未变化、翻页或滚动加载失败 | 暂停，避免无限循环 |
| 点击后进入会话但未发出默认招呼语 | 待核对并暂停，提示用户在平台开启默认招呼语 |

## 11 界面要求

使用一个扩展弹窗完成设置、开始、停止和结果查看，不要求首版制作独立工作台或复杂侧边栏。

设置区展示搜索词、当前城市、筛选条件、额度，以及“使用平台默认招呼语，请先在平台开启”的固定提示。首次使用的风险说明需用户主动确认，可在设置区重新查看。运行区展示运行状态、当前处理位置、已确认沟通数、待核对数、失败数、跳过数及已用发送额度。结果日志至少包含时间、岗位、公司、结果、证据类型和原因。

单独提供待核对列表及原始岗位链接。开始按钮在运行中禁用；停止、异常及刷新后的界面状态必须与任务记录一致。任务未进行时不展示虚假的“正在运行”。

## 12 本地数据与隐私

配置、任务摘要、发送尝试和已沟通历史保存在本地扩展存储中，不启用云端同步、遥测、模型 API 或第三方数据服务。

| 记录 | 最小字段 |
| --- | --- |
| 任务 | 任务 ID、配置快照、城市、起止时间、状态、停止原因、计数 |
| 岗位 | 岗位 ID、标题、公司、链接；可靠可见时保存招聘者标识 |
| 发送尝试 | 任务 ID、岗位 ID、尝试时间、点击前沟通入口状态、结果、证据类型、错误原因 |
| 风险确认 | 确认时间、确认的说明版本 |
| 本次跳过 | 任务 ID、岗位 ID、原因，不作为永久发送去重依据 |
| 额度 | 浏览器配置文件内的日期、时区、发送尝试数 |

默认保留最近 30 天详细运行日志，保留已沟通及待核对记录用于去重，不在达到固定条数时静默删除去重历史。提供本地存储用量提示；空间不足时在发送前暂停，不能在无法保存记录时继续发送。

当日额度以浏览器当前本地日期计算，记录时区；时区变化需提示并暂停核对，避免静默重置额度。多账号不属于首版，用户切换账号应使用独立浏览器配置文件。

不读取或存储密码、Cookie、令牌、简历文件和完整聊天历史。公开仓库只使用虚构岗位及文案；截图、日志、浏览器用户目录和真实求职数据不入库。

## 13 验收标准

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| AC-01 | 输入 3 个关键词 | 分别提交 3 次搜索，跨词重复岗位只处理一次 |
| AC-02 | 搜索列表延迟更新 | 不使用上一关键词的旧卡片执行发送 |
| AC-03 | 筛选条件无法应用 | 暂停并指出条件，不静默放宽 |
| AC-04 | 修改条件后重启任务 | 上次仅因不匹配而跳过的岗位重新参与筛选 |
| AC-05 | 薪资档位 | 仅接受平台档位；搜索后 URL 薪资参数或选中状态不符时暂停，不发送 |
| AC-06 | 默认招呼语成功 | 点击当前岗位「立即沟通」后，存在与该岗位关联的成功证据才记为已沟通；全程无文字输入 |
| AC-07 | 默认招呼语未开启 | 点击后进入会话但无本次消息时，记为待核对并暂停，提示开启默认招呼语，不补发 |
| AC-08 | 按钮已点击但未发送 | 不计入已确认沟通；占用尝试额度并进入待核对，不自动重发 |
| AC-09 | 网络中断或页面刷新 | 已开始的发送尝试仍可找到，重启后不重复发送 |
| AC-10 | 历史去重 | 新任务跳过已确认沟通的岗位；同公司不同 HR 不被错误合并 |
| AC-11 | 本次和当日额度 | 包含不确定尝试；跨任务累计，达到任一额度后不再尝试 |
| AC-12 | 停止 | 停止标志生效后没有新的发送动作；已有不确定尝试保留待核对 |
| AC-13 | 关闭和重开弹窗 | 任务继续，重新打开显示当前任务状态；刷新岗位页后不自动续发 |
| AC-14 | 多标签页 | 同一配置文件只能有一个运行任务 |
| AC-15 | 验证码和限制 | 自动暂停且不执行绕过操作 |
| AC-16 | 无结果和翻页 | 无结果正常切词；翻页无变化暂停，不死循环 |
| AC-17 | 未知弹窗和错误目标 | 不盲点或点错岗位，显示暂停原因 |
| AC-18 | 本地隐私与存储 | 无第三方数据上传；存储失败时不继续发送 |
| AC-19 | 插件自身导航 | 切换关键词或翻页导致页面重载后，凭有效令牌继续；用户手动刷新后不续发 |
| AC-20 | 首次风险确认 | 未确认风险说明时开始按钮不可用 |

纯函数测试覆盖筛选、去重状态及额度；模拟页面测试覆盖异步列表、弹窗、目标核验、假成功和停止；真实页面验收单独进行，由用户在实际账号下验证少量经授权的消息。真实验收不作为文档提交或后续纯本地开发的前置条件。

## 14 成功指标

首版先追求流程正确性：自动化验收中误记发送成功、重复发送和停止后新发消息均为 0；所有结果不明的发送进入待核对；真实页面的成功数与可见证据逐条一致。

节省时间、有效岗位占比和 HR 回复率可在实际使用后人工评估，首版不新增跟踪服务，也不将 HR 回复率作为自动发送正确性的判据。
